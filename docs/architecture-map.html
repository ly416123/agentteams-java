项目概览

设计理念：控制面数据库是控制面业务状态与任务状态的权威来源；Kubernetes CRD 与 MinIO 对象内容分别由 Kubernetes 与对象存储作为事实源，消息总线负责事件搬运，gRPC 负责任务交付。

Push 式任务交付

Control Plane 写数据库 + Outbox，NATS 承载持久化事件，Gateway 通过 gRPC 双向流交付任务， Agent 在流上确认与上报进度。

事务发件箱模式

领域事件与业务状态在同一本地事务内写入 domain_events + outbox_events， 提供至少一次投递语义；达到重试预算后尝试转入 deadletter.events，死信发布失败则继续重试。

全链路幂等与并发控制

REST 层 Idempotency-Key、执行事件按 eventId 去重、命令序列号单调递增； 乐观锁（version 字段）+ FOR UPDATE SKIP LOCKED。

部署架构

Kubernetes 集群内的应用组件拓扑与外部基础设施依赖；Kind 开发清单、Helm Chart 和生产环境采用不同口径。Manager 作为可选服务单独列出，Chart 默认关闭。

Kind 开发基础设施

deploy/kind-dev-infra.yaml 提供开发用 PostgreSQL、NATS JetStream 和 MinIO。PostgreSQL 是 StatefulSet，数据目录由 volumeClaimTemplates 声明 PVC（5 Gi）。

Helm Chart

deploy/helm/agentteams-java 只渲染应用及其配置、策略和可观测性资源，不自带 PostgreSQL、NATS 或 MinIO StatefulSet。默认值中的 NATS / Outbox 开关是裸应用与 Chart 配置，依赖由部署环境提供。

生产依赖

生产使用外部 PostgreSQL、NATS JetStream 和对象存储，并通过 values 与 Secret 注入连接信息。Chart 默认 manager.enabled=false；未显式开启时不渲染 Manager Deployment、Service 及其关联资源，开启时还需提供 manager.existingSecret。
