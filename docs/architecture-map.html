项目概览

设计理念：数据库是唯一事实来源，消息总线负责事件搬运，gRPC 负责任务交付。

Push 式任务交付

Control Plane 写数据库 + Outbox，NATS 承载持久化事件，Gateway 通过 gRPC 双向流交付任务， Agent 在流上确认与上报进度。

事务发件箱模式

领域事件与业务状态在同一本地事务内写入 domain_events + outbox_events， 保证至少一次投递（At-Least-Once）。

全链路幂等与并发控制

REST 层 Idempotency-Key、执行事件按 eventId 去重、命令序列号单调递增； 乐观锁（version 字段）+ FOR UPDATE SKIP LOCKED。

模块详解

点击卡片展开每个模块的职责、核心组件与关键设计。

contracts — 协议契约层 gRPC 双向流协议的唯一持有者 contracts/src/main/proto/agent_channel.proto ▶

定义 Agent 与 Gateway 之间全部通信协议，是唯一持有 agent_channel.proto 的模块。protobuf 生成代码为构建产物，不入库。

组件说明
AgentMessageAgent → Gateway 信封，10 种变体：hello / task_accepted / task_progress / task_heartbeat / task_completed / task_failed / config_applied / ack / error / agent_heartbeat
ServerMessageGateway → Agent 信封，5 种变体：ready / task_assigned / config_changed / ack / error
EventMetadata统一事件头：event_id / agent_id / task_id / attempt_id / sequence / expected_version / lease_id / occurred_at
ProtocolCompatibility版本协商：同 major 且 peer minor ≤ local minor 才兼容；新端可接受旧端，旧端拒绝新端
Connect RPCrpc Connect(stream AgentMessage) returns (stream ServerMessage) — 单双向流承载全部通信

演进策略：严格追加式变更（新 tag / 新字段），删除必须 reserved；oneof 扩展不破坏旧端，由 AgentChannelContractTest 用未知字段模拟未来协议锁定该保证。

domain — 领域模型层 纯 DDD，零依赖，非法状态不可表示 domain/src/main/java/io/agentteams/domain ▶

纯 JDK 实现的框架无关领域层（16 主源码 + 4 测试），全部使用 Java 17 语言特性（record / sealed interface / switch 表达式）。

组件说明
Task（聚合根）不可变聚合：phase / version / attempt / processedEventIds 幂等集合；状态变更仅能经领域服务驱动（next() 包私有）
TaskTransitionService状态机引擎：幂等检查 → 乐观锁 → 合法性 → 租约校验 → 失败详情规则；独立 renewLease() 续租路径
TaskPhaseDRAFT → QUEUED → ASSIGNED → ACCEPTED → RUNNING → SUCCEEDED / FAILED / CANCELLED
TaskTransitionResultsealed interface：AppliedTransition / DuplicateTransition（幂等命中不抛异常）
FailureInfo失败码 + 脱敏消息；内建正则脱敏器覆盖 plain / JSON / URL 三种密钥形态
AgentPhasePROVISIONING / READY / BUSY / DRAINING / OFFLINE / FAILED（Agent 域观察视图）

异常体系：DomainException → IllegalTaskTransitionException / StaleTaskVersionException / LeaseNotActiveException，均携带结构化诊断字段，便于上层映射 HTTP / gRPC 错误码。

application-contracts — 应用端口契约 六边形架构的出端口定义 application-contracts/src/main/java/io/agentteams/application/api ▶

零运行时依赖的纯接口 + Record 层（7 个文件），被 control-plane / agent-gateway / manager 三方共同引用。

端口方法消费方
TaskCommandPortcreate(idempotencyKey, command)manager → control-plane（任务创建）
ExecutionEventPortapply() / renewLease()gateway → control-plane（执行事件 / 租约续期）
ConfigEventPortapplied(command)gateway → control-plane（配置应用回执）

关键设计：命令 Record 紧凑构造器做严格防御式校验；FailureMessageSanitizer 在命令构建时自动脱敏；Envelope 携带 schemaVersion 支持协议演进。

agent-gateway — Agent 网关 gRPC 双向流 + NATS 消费 + 可靠命令交付 agent-gateway/src/main/java/io/agentteams/gateway ▶

Spring Boot 应用（44 主源码 + 20 测试），全部逻辑集中在单一包 io.agentteams.gateway。

组件说明
AgentChannelService双向流核心：Hello → 认证 → 协议协商（v2.3）→ 连接注册（current-session 唯一）→ 命令重放 → 事件路由
ConnectionRegistry连接池：per-Agent 当前连接唯一，新连接注册自动终止旧连接
CommandDeliveryServiceAt-Least-Once 交付：持久化命令 → 推送 → 确认光标（gateway_ack_cursors）；重连后只重放未确认命令
InboundEventHandler入站事件统一处理：元数据校验 → event_id 幂等 → 分派 → Ack 推进
ControlPlaneGatewayApplicationHandler桥接 ExecutionEventPort / ConfigEventPort，将 Agent 事件转为控制平面领域命令
SessionTokenAuthenticatorSHA-256 Token 认证，查 agent_sessions 表校验 agentId 匹配 + 未过期
NatsGatewayEventConsumer消费 task.events.* + agent.events.*，分派到 TaskAssignedCommandHandler / ConfigChangedCommandHandler
4 个 Jdbc StoreAgentState / Session / CommandEvent（序列 + 交付 + 确认光标）/ InboundEvent（幂等）

关键设计：所有 Port 接口提供 @ConditionalOnMissingBean 的 Noop 实现，无外部依赖时可独立测试运行。

runtime — 运行时 SPI Agent 侧运行时抽象，纯 Java 库，无 Spring runtime/src/main/java/io/agentteams/runtime ▶
组件说明
AgentChannelClient协议状态机：DISCONNECTED → CONNECTING → READY / RECONNECTING / REJECTED / CLOSED；租约管理（从 expiresAt 续期）；重连退避
GrpcAgentChannelPortgRPC 传输层；streamGeneration 代际隔离——旧流回调不影响新流
GatewayRuntimeAdapter协议 ↔ 运行时桥：expectedVersion 递增、同 attempt 去重、新 attempt 取消替换、同步完成竞态防护
QwenPawHttpRuntimePort官方 QwenPaw HTTP/SSE API：POST /api/console/chat、SSE 解析、assistant 消息聚合、请求取消（terminal CAS）
JsonLinesQwenPawProcessPort外部进程边界：JSON Lines stdin/stdout；三级优雅关闭（stop → waitFor → destroy）
RuntimeConfigCoordinator配置两阶段协调：stage → activate / discard；同版本同 checksum 幂等、异 checksum 拒绝
FakeRuntime测试 / 模拟实现，含并发上限与生命周期管理

可扩展性：AgentRuntimeRegistry 支持多运行时注册；QwenPawProcessPort 抽象使子进程边界可替换为 sidecar。

agent-worker — QwenPaw Agent Worker 轻量进程：gRPC ↔ QwenPaw HTTP/SSE 桥接 agent-worker/src/main/java/io/agentteams/worker ▶

纯 Java + gRPC + JDK HttpClient 的轻量进程（无 Spring），核心类 QwenPawWorker（585 行）完成全部编排。

  • 任务分发：resultGates（每任务锁）+ runningTasks / pendingResults 处理「任务先到 vs 结果先到」竞态；异常仍 Ack 防毒消息
  • 配置闭环：ConfigChanged → 拉取 / 校验 manifest（SHA-256 + 大小）→ 文件暂存（路径穿越防护 + 原子写入）→ 两阶段激活 → ConfigApplied 回执
  • 可运维性：WorkerHealthServer（TCP 就绪探针）、断线重连退避、优雅关闭钩子
  • 配置：21 个环境变量，唯一必填 AGENTTEAMS_AGENT_ID；协议版本固定 v2.3
manager — DeepSeek Manager 编排 自然语言 → 结构化任务意图 → 幂等建单 manager/src/main/java/io/agentteams/manager ▶

纯客户端库（无 Spring Boot 启动类）：将 prompt 交给 OpenAI 兼容模型，校验结构化输出后经 TaskCommandPort 幂等创建任务。

组件说明
ModelProvider 族OpenAICompatibleProvider + DeepSeekProvider + FallbackModelProvider（主备切换）+ RetryPolicy（指数退避 ≤5 次）
ManagerSessionService核心门面：构造请求 → 调用 provider → 审计 → 解析输出 → 授权工具调用
ControlPlaneCreateTaskToolCreateTaskIntent → JSON spec；SHA-256 内容哈希幂等键（manager- 前缀）
ManagerToolRegistry工具调用权限检查 + 审批检查双保险
JdbcModelCallAuditor审计日志：凭据先脱敏再 SHA-256 哈希，绝不落明文

错误分类：ModelProviderException 8 类 Category，可重试性（网络类）与不可重试性（认证 / 协议类）贯穿全链路。
