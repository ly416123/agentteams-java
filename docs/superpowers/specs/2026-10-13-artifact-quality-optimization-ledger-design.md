# 成果物质量优化台账设计

## 背景

成果物质量问题、生成失败、整改动作和复检结果目前分散在任务结果、评测 JSON、评测证据目录和开发计划中。用户无法在一个系统入口回顾某类成果物反复失败的原因、采用过的优化方式以及优化是否有效。现有父任务结果清单只负责暴露父任务明确选定的最终交付文件，不适合作为过程记录；过程信息也不应混入 PDF 正文。

## 目标

增加系统级、独立可访问的“成果质量优化”台账，持续记录成果物从生成、质量检查、整改到复检的轨迹。台账提供独立页面和受授权查询 API，允许按时间、项目、任务、成果物、状态和问题类型检索。历史评测与修复记录应尽可能回填，并明确区分实时采集与历史重建。

## 设计决策

采用追加式质量事件模型，而非在任务详情里保存一份可覆盖的优化摘要，也不把记录限制在评测报告中。数据库是事实来源；Control Plane API 提供按授权范围查询；Console 的独立页面提供浏览、过滤和任务/成果物下钻。任务详情和成果物下载链路保持现有职责，PDF 正文不包含优化过程。

## 数据模型与记录内容

每条记录是一个不可变事件，至少关联 `taskId`、`runId`；存在具体文件时还关联成果物名称、文件 ID 或 manifest 引用及 SHA-256。未产生文件的失败记录仍可关联任务和 Run。事件按时间及轮次形成一条轨迹，覆盖：

1. 成果物生成开始、成功或失败；失败时记录稳定原因分类和脱敏说明。
2. 质量检查结果；低质量时记录问题分类、检查项、分数或门禁结果及简短依据。
3. 优化动作；记录实际采取的措施、所针对的问题及动作来源（自动流程、人工处理或外部修复）。
4. 优化后的复检；记录复检检查项、结果、分数变化和成果物版本/摘要。
5. 最终状态；标识通过、仍不合格、生成失败或证据不足。

事件还应带有来源类型（实时采集或历史重建）、来源引用、重建可信度和创建时间。失败原因、质量缺陷和优化动作采用可扩展的分类码并保留短说明，便于统计而不丢失必要上下文。只保存有界、脱敏的诊断信息；不保存访问凭证、预签名 URL、完整提示词、原始搜索响应或整份成果物正文。

## 数据流

1. 生成流程在开始、文件上传结果和失败出口写入生成事件。
2. 确定性 PDF 检查、语义/内容评审和其他质量门禁将实际检查结果写入质量事件。
3. 优化或重跑流程只在动作真实执行后记录措施；复检后追加结果事件，并与本轮成果物版本关联。系统不得仅凭“再次运行”推断质量已改善。
4. Control Plane 以追加方式持久化事件，并通过任务/Run、成果物引用和作用域建立关联。重复投递使用稳定事件 ID 或幂等键去重。
5. 查询 API 按当前用户可访问的组织、Tenant、Project 范围过滤；不提供绕过项目成员关系的全局明细读取。
6. Console 独立台账页展示事件时间线、失败原因、问题、优化措施、复检结果、来源可信度，并链接到有权访问的任务详情或成果物。

## 历史回填

历史资料来源包括 `eval/reports/` 中的确定性评测报告、DeepEval/最终评审报告，以及 `docs/superpowers/plans/` 中明确记录的修复和重跑事实。回填工具必须可重复执行，并以来源文件摘要与记录键保证幂等。

历史数据只录入来源材料可证明的事实。例如评测报告可证明某轮 PDF 缺失或门禁失败，计划文档可能证明后续修复和复测；仅有版本文件名或时间先后不能证明两次运行之间的因果关系。不能确认的具体优化手段、成果物关联或优化效果保持空缺，并在页面标记“历史重建”及来源引用/可信度，不伪装成实时事件。回填范围覆盖仓库现存且可安全关联的历史报告和计划；若旧记录缺少任务/Run/文件 ID，则保留评测用例、报告时间和来源文件标识作为弱关联，不创建虚构 UUID。

## 权限与隐私

- 数据库记录携带规范化组织、Tenant、Project UUID 作用域；写入方必须从可信任务执行上下文解析作用域，不能接受模型自报 Scope。
- 页面和 API 仅返回调用者已授权的记录。跨项目统计需走已有的系统管理员授权，不因“系统级台账”自动扩大普通用户的读取范围。
- 优化动作说明、缺陷说明和评审依据经过长度限制及敏感字段脱敏；不得存储密钥、令牌、密码、签名下载地址或原始工具正文。
- 历史来源文件路径仅作为内部审计引用，不直接向无权用户暴露本地文件路径。

## 失败处理

- 质量事件写入失败不能改变任务、文件上传或已有质量门禁的最终状态；应通过可靠的重试/事件交付机制补记，并暴露采集状态，避免将“没有记录”误认为“质量通过”。
- 事件内容不完整或来源证据不足时标记 `INCONCLUSIVE`，不推导通过或优化成功。
- 重复或乱序事件按幂等键去重，并以事件发生时间和序号排序；迟到事件追加，不覆盖已存历史。
- 历史回填遇到格式错误或无法关联的数据应跳过该项并生成脱敏错误摘要，不能中止其他记录的导入。

## 不在本次范围

- 不实现自动重写、自动修复或无限质量迭代；本设计记录现有优化动作和效果。
- 不把所有子任务成果物自动加入父任务最终结果；父任务仍只展示其 Manifest 明确选择的文件。
- 不把优化轨迹写入 PDF 或其他面向最终读者的交付正文。
- 不允许普通用户跨组织、Tenant 或 Project 浏览全系统数据。

## 验收标准

1. 生成失败、低质量检查、优化动作、优化后复检和最终状态可按任务/Run/成果物组成有序、不可覆盖的轨迹。
2. 未产生文件的生成失败也能进入台账；具体文件的轨迹能关联到文件 ID/摘要和版本。
3. 独立页面支持筛选与查看详情；API/页面均严格遵守已有组织、Tenant、Project 授权边界。
4. 质量事件缺失或来源不完整时显示“未知/证据不足”，不得显示成通过。
5. 历史回填幂等，可从现存评测报告和计划记录中回填可证实的信息；每条回填记录明确显示来源与可信度，对证据未记载的优化措施/结果保持未知。
6. 事件写入、查询、回填和页面测试覆盖重复、乱序、迟到、无文件失败、跨项目越权、脱敏以及部分损坏历史报告。
7. PDF 正文和原有父任务最终成果物选择规则不变。
