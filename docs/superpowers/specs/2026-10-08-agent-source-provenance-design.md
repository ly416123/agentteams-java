# Agent 搜索来源可信证据链设计

**状态：** 待用户审阅  
**范围：** 为 AgentTeams 多 Agent 任务建立从真实搜索工具返回到最终答案引用的可验证来源证据链，并让评测器据此判断 `source_citation`。

## 背景与目标

当前 `agentteams-mcp-tools` 的搜索响应是 `List<String>`，来源 URL 与标题只存在于文本块中。AgentScope 的工具完成事件仅保留工具调用状态，不带工具响应正文；Control Plane 也没有任务级搜索来源记录。因此，评测器无法证明答案引用来自本次任务实际检索到的来源，只能输出 `INCONCLUSIVE`。单纯让模型自报结构化引用不能建立来源真实性。

目标是记录由受信任搜索工具实际返回的来源元数据，并按任务与执行 Run 关联。评测器能够把最终答案中的引用与该 Run 的来源集合比较；来源证据缺失、关联不可信或格式不可判定时仍输出 `INCONCLUSIVE`。

## 方案选择

采用跨 `agentteams-java` 与 `agentteams-mcp-tools` 的可信证据链：搜索 MCP 返回结构化来源；调用携带由平台认证的任务执行上下文；来源元数据由受信任边界写入 Control Plane；评测只读该 Run 的记录。拒绝以模型自报或普通客户端传入的 task ID 作为可信证据。原始搜索正文不写入证据表或评测报告。

## 架构与数据流

1. Worker 为每个执行中的 MCP 调用提供不可由模型控制的任务、Run、尝试和工具调用关联。上下文必须来自已验证的执行身份或租约，不能仅信任 MCP 参数或可伪造的自定义头。
2. `agentteams-mcp-tools` 将上游搜索响应解析为有界的结构化结果项。每项至少包含标题与 URL；无效 URL、超长字段、重复 URL 和超过上限的结果按确定性规则清理或拒绝。工具仍可返回模型可读文本，但同时提供结构化来源数据。
3. 搜索 MCP 在返回结果时，将结构化来源元数据及可信调用上下文提交给 Control Plane 的内部写入接口。Control Plane 校验服务身份、任务/Run/尝试关联及调用权限后，保存来源记录。失败不伪造证据；调用结果可以正常返回，但该 Run 的来源证据完整度标为未知/不完整，最终来源门禁为 `INCONCLUSIVE`。
4. Control Plane 的 Evaluation Evidence Bundle 按组织、租户、任务、Run 限定查询来源记录，并仅向评测器提供稳定来源引用、规范化 URL、标题和证据完整度。报告只保存来源引用及判定，不复制搜索正文或凭证。
5. `source_citation` 从最终答案提取明确的 URL 引用，与同一 Run 记录中的规范化 URL 精确比较。全部可判定引用均命中且来源证据完整时通过；明确不匹配时失败；缺来源记录、来源摄取失败、证据截断或答案引用无法可靠解析时为 `INCONCLUSIVE`。不得仅凭域名相似或模型自报的“已检索”声明通过。

## 存储与安全边界

Control Plane 增加只追加的任务来源证据记录，字段至少包括：组织/租户、task ID、run ID、attempt ID、工具调用 ID、规范化 URL、标题、搜索提供方标识、记录时间和来源哈希。唯一键应支持幂等重试；同一调用的相同来源不得重复计数。查询强制限定授权范围与 Run。

不存原始搜索响应、查询正文、访问令牌、认证头或模型完整输出。URL 规范化只允许 HTTP/HTTPS，删除 fragment，拒绝 userinfo；不主动访问引用 URL。评测报告输出的证据引用使用稳定 ID，不包含内部 API 地址或秘密信息。来源表应通过迁移建立索引和必要的范围约束；保留周期沿用任务证据策略，具体实现不得超出项目现有数据保留约束。

内部写入接口必须认证 MCP 服务身份，并验证该执行身份确实有权为目标 task/run 写入证据。请求体中的 task/run 标识本身不构成授权。接口需限制单次来源数量、字段长度和请求大小，并提供幂等键。

## 组件职责

- **Worker / MCP 调用边界：** 提供不可由模型修改的执行关联；维持现有工具成功/失败生命周期事件，不记录工具正文。
- **agentteams-mcp-tools 搜索适配器：** 把上游文本结果解析成结构化来源，保留模型所需的可读结果，并在完成前尝试写入来源证据。
- **Control Plane 来源证据服务：** 认证调用方、验证任务范围、规范化并持久化来源，按 Evidence Bundle 权限读取。
- **Evaluation：** 只消费 Bundle 中的来源证据与最终答案；根据来源完整度区分失败与不确定。

## 失败处理与兼容性

- Control Plane 来源写入失败、权限不匹配、Run 无法确认、数据超限或响应无法解析：不创建可信证据，并记录不含敏感内容的稳定失败分类；来源断言为 `INCONCLUSIVE`。
- 旧任务与没有结构化来源能力的 MCP 工具继续工作；其来源断言保持 `INCONCLUSIVE`，不能从旧文本日志反向宣称可信。
- 多次执行按 Run 隔离，不能用其他任务、其他 Run 或其他租户的 URL 命中当前引用。
- 如果结果中没有显式 URL 引用，按用例契约判定；正向来源引用用例要求至少一个可解析引用。

## 验收标准

1. 结构化来源确实来自搜索提供方响应；客户端或模型不能凭空为任意 task/run 注入来源。
2. 来源记录受组织、租户、task、Run 范围限制；跨租户、跨任务及无权 Run 读取/写入均失败。
3. 同一搜索调用重试幂等；不同 Run 之间来源不串用。
4. 合法 URL 引用命中本 Run 来源时 `PASSED`；完整证据中的明确伪造 URL 为 `FAILED`；缺失或不完整证据为 `INCONCLUSIVE`。
5. 搜索结果正文、查询正文、凭证、认证头和预签名地址不进入来源表、Evaluation 报告或普通日志。
6. `agentteams-mcp-tools` 与 Control Plane 分别有解析、规范化、鉴权、隔离、幂等、失败和脱敏测试；Runner 的离线契约测试覆盖三种门禁结果。只有在 L5 更新后执行真实评测，才可更新真实 L5 报告。

## 暂不纳入

- 搜索结果质量或事实正确性判定。
- 对引用 URL 发起联网验证、抓取页面或评估页面内容。
- 语义 Judge、引用相关性打分及人工审核工作流。
- 对历史任务文本日志做回填或推测性来源恢复。
