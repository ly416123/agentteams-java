# 父任务最终交付物设计

## 背景

任务文件目前记录在实际产出文件的任务（通常是子任务）下。父任务的运行结果页面只展示父任务自己的 Result Manifest，因此用户即使看到父任务成功，也可能找不到子任务产出的最终 PDF。文件表和对象存储已经保留了文件来源，无须复制文件字节。

## 目标

父任务成功后，用户可在父任务的“运行结果与成果物”区域查看并下载本次执行中由父任务明确选定的最终文件；未选定的子任务输出只保留在子任务详情中。下载仍执行父任务的项目/团队授权，并保留来源子任务信息。

## 行为规则

1. 聚合阶段，父任务读取成功子任务的结果和 `taskFiles` 元数据，选择需要作为最终交付的文件；只有父任务最终 Manifest 明确引用的文件才出现在父任务结果中。未被引用的候选文件不自动汇总。
2. Manifest 引用包含源任务 ID、源文件 ID 和展示元数据；文件内容继续存储在原对象位置，不复制二进制内容。
3. 父任务结果接口返回被选中的交付物及来源子任务；页面在父任务结果区提供名称、类型、大小、来源子任务和下载操作。原有 Manifest 产物继续展示。
4. 下载时先验证调用者对父任务的作用域，再验证引用文件属于同一运行树中的成功任务、文件角色为 `OUTPUT` 且状态为 `AVAILABLE`，最后为原文件生成短时下载跳转。不能仅凭任意子任务 ID 绕过父任务授权。
5. 子任务失败、文件缺失、引用不在本次运行树中或引用文件为 `INPUT` 时，发布校验拒绝该引用；多个子任务产生同名文件时以源任务和文件 ID 区分。

## 不在本次范围

- 不迁移或复制现有 PDF 对象。
- 不把所有子任务输入文件暴露给父任务。
- 不实现人工挑选、重命名或删除交付物的工作流。

## 验收标准

- 对多智能体 PDF 用例，只有父任务 Manifest 明确选择的 PDF 出现在根任务结果中，并显示来源子任务。
- 使用父任务授权可下载对应文件；无父任务权限、非该运行树文件及 INPUT 文件都不能通过此入口下载。
- 普通非多智能体任务的结果展示保持兼容。
- 自动化测试覆盖子任务文件汇总、来源标注、不可用文件过滤和下载授权边界。
