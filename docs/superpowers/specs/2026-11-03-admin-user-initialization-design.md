# 管理员用户初始化工具设计

**设计状态：** 方案方向已确认，等待规格文档审阅。

## 背景

当前身份管理页把内部用户创建、外部用户初始化、身份映射和组织成员授权拆成多项操作。创建内部用户需要管理员手工填写 OIDC `subject`，外部用户初始化又生成独立的合成主体；这些步骤不会创建可登录的 Keycloak 账号，也不会自动完成组织成员授权。

L5 Console 当前信任 `agentteams` Realm。若要让接入用户登录 Console，必须在该 Realm 创建本地账号。本工具为外部业务系统用户创建独立的 AgentTeams 登录账号，并把 Keycloak 登录主体、外部身份映射和组织成员关系关联起来。原业务系统密码不会读取、复制或迁移。

## 目标

- 在一个管理员向导中创建可登录的 AgentTeams 账号、外部身份映射和组织成员关系。
- 平台管理员可为任意组织初始化用户；组织管理员只能为本组织初始化用户。
- 自动生成一次性临时密码，并要求用户首次登录时修改密码。
- 账号或映射冲突时明确拒绝，不自动合并既有身份。
- 密码只通过 HTTPS 返回给操作管理员，不写入数据库、审计记录或日志。

## 非目标

- 不导入或同步原业务系统密码。
- 不接入原业务系统的 OIDC 登录，也不增加多 Issuer 登录能力。
- 不创建 Keycloak Realm、业务系统集成或组织。
- 不在本次向导中授予租户或项目角色。
- 不通过邮件发送密码或重置链接。
- 不在本次范围内为 L5 配置 TLS；L5 当前 HTTP 入口必须先启用 HTTPS，工具才能开放创建操作。

## 领域模型

- **Keycloak 账号：** `agentteams` Realm 中的本地登录凭据。Keycloak 用户 ID 是 OIDC `sub`。
- **内部用户：** AgentTeams 管理域记录，`subject` 必须与 Keycloak `sub` 相同。
- **外部身份：** `(integrationId, externalOrganizationId, externalUserId)` 唯一标识映射到内部用户；它不产生登录凭据。
- **组织成员关系：** 组织、主体 `sub` 和组织角色的关联；它负责授权，不负责认证。
- 每个接入用户因此有一份 AgentTeams 本地密码；原系统账号可继续保留，但两份凭据彼此独立。

## 方案选择

| 方案 | 登录行为 | 代价 | 结论 |
|---|---|---|---|
| 只建立外部身份映射 | 不能凭映射登录 Console | 还需外部 IdP 登录支持 | 不采用 |
| 接入业务系统 OIDC | 复用原系统登录 | 需要配置 IdP、Issuer 和身份关联；L5 当前未配置 | 后续可扩展 |
| 创建本地 Keycloak 账号 | 使用独立 AgentTeams 密码登录 | 需要安全创建账号并交付临时密码 | **当前采用** |

## 使用流程

### 1. 选择身份来源

- 管理员从自己可管理的现有集成中选择一个集成。
- 集成的 AgentTeams 组织作为成员关系的目标组织，并以只读信息显示，不能单独改选，避免集成与目标组织不一致。
- 平台管理员可选任意组织内的集成；组织管理员只看到本组织的集成。

### 2. 填写账号和外部身份

- 必填：登录用户名、显示名称、外部组织 ID、外部用户 ID。
- 登录用户名可根据外部用户 ID 预填，但管理员可以修改；需满足 Keycloak 用户名规则并保持 Realm 内唯一。
- 不要求邮箱；密码采用管理员线下转交的一次性临时密码。

### 3. 选择组织角色并确认

- 默认角色为 `MEMBER`；可选角色沿用现有组织角色：`OWNER`、`ADMIN`、`MEMBER`、`AUDITOR`。
- 确认页同时展示 Realm、登录用户名、目标组织、外部身份和将授予的角色。
- 选择 `ADMIN` 或 `OWNER` 时，明确展示权限范围后再提交。

### 4. 创建完成并交付临时密码

- 成功页展示登录用户名和临时密码，并提供复制操作；密码只在本次成功响应中返回一次。
- Keycloak 账号设置为启用状态，并带 `UPDATE_PASSWORD` Required Action；用户首次登录 Console 后必须设置自己的新密码。
- 管理员离开成功页后不再显示原临时密码。若用户遗失密码，管理员可重新生成一次性临时密码；旧密码立即失效，操作需审计。
- 页面注明这是独立的 AgentTeams 密码，不是业务系统密码。

## 界面与权限

- 入口放在「系统设置 → 身份与权限」下，命名为「初始化用户」。
- 仅拥有平台管理员或目标组织管理员权限的用户可见并使用。
- 服务端以认证主体和数据库中的管理角色校验权限。平台管理员作用于全平台；组织管理员必须对集成所属组织具有管理权限。
- 新接口复用现有 `external-user:manage` 能力，并对集成及其组织执行服务端作用域校验；不得信任前端提交的角色、组织权限或集成所属关系。
- 非管理员直接请求接口返回 403；前端隐藏入口并对直接路由显示友好无权状态。
- 组织管理员不能选择其他组织的集成或写入其他组织的成员关系。

## 服务端与数据流

新增一个原子化用户初始化服务，避免浏览器串联当前分散接口。建议接口：

```text
POST /api/v1/management/user-initializations
POST /api/v1/management/user-initializations/{id}/temporary-password
```

初始化请求包含集成 ID、外部组织 ID、外部用户 ID、登录用户名、显示名称和组织角色，并要求 `Idempotency-Key`。重新签发接口只重置指定内部用户的临时密码，不修改身份映射和组织角色。接口执行以下步骤：

1. 校验认证主体、管理员作用域、集成状态、目标组织及输入格式。
2. 创建持久化初始化操作记录，保存请求摘要、调用者、作用域、Keycloak 用户 ID 和恢复阶段；记录中不保存密码。
3. 检查 Keycloak 用户名和外部身份映射是否已存在。若外部身份已映射到其他内部用户，拒绝请求，不覆盖映射。
4. 使用仅供 Control Plane 后端使用的 Keycloak Realm 服务账号，在 `agentteams` Realm 创建禁用状态的用户，设置随机临时密码和 `UPDATE_PASSWORD` Required Action。浏览器不得持有 Keycloak 管理凭据。
5. 在一个数据库事务中写入 `management_users`、`external_identities`、`organization_memberships` 和完成态幂等信息。三者使用同一 Keycloak `sub` 关联。
6. 数据持久化成功后启用 Keycloak 用户，并把初始化操作标记为完成。全部步骤成功后，才通过 HTTPS 将用户名和临时密码返回一次。
7. 任何跨系统失败都保持账号不可登录并记录可恢复阶段。相同幂等请求可继续恢复，不得重复创建用户或成员关系，也不得返回已失效或可能已被看到的旧密码。

新增初始化操作表（例如 `management_user_initializations`）记录幂等键、请求摘要、目标用户及状态（`PREPARING`、`KEYCLOAK_CREATED`、`DATABASE_COMMITTED`、`COMPLETED`、`RECOVERY_REQUIRED`）。它只保存恢复所需的非秘密元数据。若成功响应丢失，重试返回「账号已初始化，需重新签发临时密码」；管理员使用第二个接口签发新密码，旧密码立即失效。

Keycloak 服务账号仅授予创建、查询用户和设置密码所需的 Realm 用户管理权限，不授予 Realm 管理员、角色管理或客户端管理权限。其凭据只存放在 Kubernetes Secret 中，由 Control Plane 读取。

临时密码在服务内存和 HTTPS 响应中短暂存在。不得持久化明文，不写应用日志、审计事件、异常消息、浏览器 Local Storage 或 Session Storage。审计记录操作者、内部用户 ID、组织、集成、授予角色和结果；外部用户 ID 可按现有审计模式记录摘要。

## HTTPS 启用门槛

- 临时密码经浏览器展示前必须经过 HTTPS。当前 L5 的 `http://192.168.122.55:30080` 和 Keycloak `http://192.168.122.55:30082` 不满足此要求。
- 前端在非 HTTPS 页面隐藏或禁用初始化提交，并说明需使用安全入口。
- 后端默认关闭凭据初始化能力；只有部署明确启用且请求经受信任 TLS 终止代理确认安全传输时才允许创建或重新生成密码。
- 未纳入本次范围的 L5 TLS 部署完成前，L5 上不能实际使用此密码初始化功能。

## 错误处理

- 用户名已存在：提示更换用户名；不关联或覆盖现有账号。
- 外部身份已绑定其他用户：提示联系管理员核查；不自动合并。
- 集成被停用、管理员越权或请求不安全：拒绝操作并返回可理解原因，不暴露跨组织资源存在性。
- Keycloak 不可用：不写入部分 AgentTeams 关系，提示稍后重试。
- Keycloak 创建成功但数据库写入失败：Keycloak 用户保持禁用；保留幂等操作状态以便安全重试或清理。
- 数据库写入成功但 Keycloak 启用失败：用户不能登录；显示初始化未完成，并允许管理员重试恢复。
- 一次性密码响应丢失：不复用旧明文；管理员重新生成新临时密码，旧密码作废并记录审计。

## 验收标准

1. 平台管理员可为任意组织内集成初始化用户；组织管理员仅能为本组织集成初始化用户。
2. 非管理员即使直接调用 API 或手工打开路由，也不能初始化用户。
3. 创建后 Keycloak 用户、AgentTeams 内部用户、外部身份映射和组织成员关系指向同一 `sub`。
4. 用户可用新用户名及临时密码进入 L5 Console，并在首次登录时被要求改密；原业务系统密码不变。
5. 成功页面只显示一次临时密码；重新生成后旧密码失效，数据库、审计和日志中没有明文。
6. 重复提交和网络重试不会产生重复 Keycloak 用户、身份映射或成员关系。
7. 角色和组织范围来自服务端校验；组织管理员不能授权其他组织。
8. 在 HTTP 环境中创建和重置临时密码均被前端与后端拒绝；TLS 部署验证后才可启用。
9. 冲突、Keycloak 不可用和跨系统部分失败均有明确提示和可恢复状态。

## 实施范围

- Console：管理员入口、初始化向导、确认页、一次性密码展示与重新生成。
- Control Plane：管理员作用域检查、幂等初始化/恢复服务、Keycloak Realm 用户管理客户端、身份映射及组织成员关系持久化、审计。
- 部署：增加专用 Keycloak 服务账号凭据的 Secret 引用和默认关闭的安全启用配置；不在本次为 L5 配置 TLS。
- 验证：覆盖授权边界、Keycloak 客户端错误/重复、数据库失败恢复、密码不落日志和 HTTP 禁用行为；完成 L5 HTTPS 门槛核查。
