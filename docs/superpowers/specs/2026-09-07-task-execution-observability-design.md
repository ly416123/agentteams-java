# 任务执行可观测与人工干预设计

## 目标

让管理后台能够实时观察任务执行过程、理解执行上下文、查看详细结果，并在任务运行期间进行可审计的人工干预。

## 现状与约束

- 控制面已经持久化任务生命周期事件、执行过程事件、进度快照、运行结果、成果物、任务树、决策记录和恢复状态。
- 控制面已经提供任务取消、暂停/恢复、重试、批准和拒绝接口，并使用版本号和幂等键保护并发操作。
- Console 当前只消费任务生命周期 SSE、执行尝试、运行记录和恢复状态，尚未消费过程事件、进度、任务树、决策和结果 Manifest。
- 不新增第二套任务状态机，不改变现有控制面状态转换规则。

## 方案

### 控制面数据流

Worker/Manager 将执行事实写入控制面投影，Console 通过以下只读接口回放：

- `GET /api/v1/tasks/{taskId}/runs/{runId}/process-events/stream`：过程事件 SSE，使用 `Last-Event-ID` 断点续传。
- `GET /api/v1/tasks/{taskId}/runs/{runId}/progress`：进度快照。
- `GET /api/v1/tasks/{taskId}/runs/{runId}/tree`：任务分解树。
- `GET /api/v1/tasks/{taskId}/runs/{runId}/decisions`：安全的决策摘要。
- `GET /api/v1/tasks/{taskId}/runs/{runId}/result`：终态结果 Manifest 和成果物元数据。

过程事件只展示请求方可见的数据；不在前端展示内部提示词、凭据或链路思维内容。事件正文优先展示安全摘要，原始 `payloadRef` 只作为可追踪引用。

### 管理端交互

任务详情页分为以下区域：

1. 执行总览：当前状态、进度、运行时间、Worker、恢复状态。
2. 实时过程：按时间倒序/正序展示过程事件，显示事件类型、摘要、时间、关联 ID；断线时显示重连状态。
3. 执行实体：Attempt、Assignment、Lease 及生命周期状态。
4. 任务分解：树状展示父任务、子任务、依赖和状态。
5. 决策记录：展示目标摘要、选定动作、证据摘要、约束、置信度和时间。
6. 运行结果：状态、结果摘要、成果物名称、类型、大小、哈希、阶段和存储引用。
7. 人工干预：根据当前状态显示暂停/恢复、批准、拒绝、取消、重试，继续沿用版本冲突确认和幂等操作反馈。

### 失败处理

- SSE 断开后使用最后游标自动重连，避免重复事件；重复事件由事件 ID 去重。
- 单个投影接口失败时只影响对应区域，页面仍保留任务状态和其他区域。
- 没有运行记录时显示明确的空状态，不把“暂无数据”当作执行失败。
- 成果物只展示元数据，不直接暴露存储凭据或内部对象存储授权信息。

## 测试策略

- API 单元测试：过程事件 SSE 解析、游标续传、进度/树/决策/结果请求。
- 前端组件测试：状态总览、过程事件、任务树、决策、成果物、干预按钮和局部错误隔离。
- 端到端测试：创建任务、排队、执行期间观察过程、暂停/恢复或取消、完成后查看结果与成果物。
- 构建验证：Console lint、TypeScript 构建，以及控制面相关测试。
