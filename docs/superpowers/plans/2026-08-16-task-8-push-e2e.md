# Task 8 Fake Agent and Push E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect the existing gRPC Agent channel to queue-to-assignment persistence and prove a complete task push lifecycle with a reconnecting Fake Agent and idempotent completion/artifact handling.

**Architecture:** The Control Plane owns scheduling, attempts, assignments, leases, task transitions, artifacts, and outbox rows. The Gateway owns the gRPC stream, durable command sequencing/replay, and inbound event deduplication. A small adapter bridges the two through explicit ports; the integration test starts both application contexts and a real gRPC server, while Testcontainers provide PostgreSQL, NATS JetStream, and MinIO.

**Tech Stack:** Java 17, Spring Boot, gRPC Java, PostgreSQL/Flyway/JDBC, NATS JetStream, MinIO Java SDK, JUnit 5, Testcontainers.

### Implementation status (2026-08-21)

Completed and verified by `TaskPushInfrastructureIT` (the implementation uses this consolidated class instead of the originally proposed `TaskPushE2ETest`). `FakeAgent` covers reconnect, acknowledgement, task completion, and configuration messages. The latest integration run passed 3/3 tests, including dual-Gateway config fanout, durable consumer acknowledgement, command deduplication, and single delivery on the active Agent connection.
